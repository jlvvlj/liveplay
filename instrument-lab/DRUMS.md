# Drum reconstruction in Instrument Lab

Open an imported song’s **Instrument Lab editor** to work on synths and drums in one instrument list and timeline. **Add drum sounds** reads the song’s existing separated drum WAV; **Add drum stem** attaches an already separated recording to this same workspace. Existing drum analyses are automatically reunited with their song’s synth analysis, preserving patches, assets, revisions and local drafts. The original sound/practice editors remain unchanged.

**Original mix** plays the imported song; **Rebuilt mix** renders every synth and drum part together on one clock. **Original stem** and **Rebuilt stem** play the selected instrument. Shape sound switches to the appropriate controls when selecting a synth or drum. Practice mutes only the selected instrument and includes both sound types in its accompaniment. The instruments panel has a play/pause button for the rebuilt mix, a draggable playhead, shared zoom buttons and slider, pinch zoom, and horizontal panning. Each instrument has Solo and Mute; multiple solos play together and mute takes priority. These controls apply to rebuilt playback and practice backing. Original audio remains available unchanged for comparison.

Each underlying analysis remains independently versioned so saving a drum cannot overwrite synth edits, or vice versa.

Analysis runs on the local backend; playback and practice run in the browser. No new model download or Python dependency is required. The output retains stereo at 44.1 kHz and supports complete songs. Sound discovery learns attack/decay patterns from this recording rather than assigning every sound to a fixed set of drum categories. Similar or continuously layered sounds can remain ambiguous.

Each discovered sound has hit times, velocities and an editable hybrid patch. The engine combines a fitted damped resonator/noise generator with a recovered example. **Recovered detail = 1** retains the example’s texture; **0** exposes synthesized percussion alone. This is explicitly a hybrid reconstruction, not a claim that oscillator parameters reproduce arbitrary samples exactly. Tune, decay, transient, tonal body, noise, brightness, drive and level are editable. The original audio assets remain immutable.

Review hits to adjust timing/velocity or add/remove detections. **Merge into…** on each instrument row transfers its events to another instrument in the same analysis, keeping the destination patch (and recovered sample for drums). Synths merge with synths, drums with drums. Review the source/destination summary, then choose **Merge tracks** to save and rebuild audio. Exact duplicate events become one event. Save any destination draft first; source edits are included in the merge. Drum original stems are summed in stereo, while melodic reference stems are re-extracted. Drum splitting is not implemented; the melodic split/move editor remains available. The pad or any MIDI key/pad plays the selected sound. Practice mutes that sound from the rebuilt accompaniment, retains velocity, and changes event spacing without transposing or stretching each one-shot. Releasing a pad does not cut its tail. Named choke groups cut earlier sounds in the same group; leave blank for overlapping tails.

## Validation

`npm run test:instruments` includes an independently authored stereo percussion fixture with two kicks, two snares, short/long hats, simultaneous hits and quiet rolls. Its sound generator does not import the drum engine. The test matches sound identity and hit times, checks quiet velocities, stereo retention, one-shot release, choke behavior and practice pitch/timing. `npm run test:integration` checks that the drum bridge reads only saved drum-stem bytes and reuses existing drum projects.

Workspace tests check mixed-engine summing, selected-instrument muting, pending drum analysis, legacy project links, and saving each engine without overwriting the other.

The 20-second reference fixture recovered all 114 labelled hits with approximately 96% precision (20 ms matching window). These are fixture results, not a real-song accuracy claim. Full-length Else–Paris (209.76 seconds) was processed end-to-end; low-energy candidates without repeated independent evidence were excluded. Real separation bleed, variable timbre and inseparable layered hits still require review. Spectral/waveform residuals measure reconstruction error and are not perceptual similarity or transcription accuracy scores.
